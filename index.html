HOW IT WORKS

S3. In the csv-raw-data-bucket properties, an Event Notification is created to trigger the Lambda function. Event type: PUT. Prefix: raw/ — all raw files are uploaded to this folder. Destination: Lambda function. Suffix: .jpg.

IAM. A role was created for Lambda as the trusted entity, with S3FullAccess and GlueServiceRole attached. A separate role was created for Glue with AWSGlueServiceRole and S3FullAccess.

AWS Glue Data Catalog. A centralized metadata repository that stores information about datasets, making them easily searchable and accessible for analytics. Glue is better suited for large-scale, complex transformations on big data, with built-in schema discovery and job orchestration. The Crawler only extracts metadata — structures, data types, and partitions — from what it finds in the S3 bucket, and saves this structured information as tables inside a selected logical database (which needs to be created beforehand). Creating this database is essential: it acts as a centralized metadata catalog, letting subsequent Glue jobs reference it as a source through high-level table schemas rather than parsing raw S3 file paths directly.

An AWS Glue Job is a serverless ETL (Extract, Transform, Load) service that runs PySpark or Python scripts to extract raw data from a source, apply business logic or data transformations, and load the cleaned output into a target destination.

HOW IT WORKS

S3. Hosted websites can communicate with or call Lambda directly, but doing so exposes AWS credentials. For this project, an Access Key ID & Secret Access Key were used only for the frontend-web-user role, created in IAM with lambda:Invoke permission.

API Gateway. Provides endpoints for frontends to communicate with backend services. Calling AWS.Lambda.invoke( ) directly from the browser would require embedding IAM credentials — API Gateway acts as a secure proxy instead. Best practices:

  • Enable CORS to allow the S3 website's domain
  • Add auth (Cognito, API Key, Lambda Authorizer)
  • Avoid hardcoding secrets

CORS allows web applications on distinct domains to access an API. The browser first asks API Gateway with an OPTIONS request ("am I allowed to make this request?"), and the API must respond with the right headers:

  • Access-Control-Allow-Origin
  • Access-Control-Allow-Methods
  • Access-Control-Allow-Headers
  • Access-Control-Max-Age
  • Access-Control-Allow-Credentials (cookies)

Lambda (the backend) must also return CORS headers in its own responses, for every method — GET, POST, and so on.

SNS. A standard topic was created — not FIFO. Its ARN was used later in the flow.

Lambda. Before creating the function, an IAM role was set up granting it permission to interact with SNS and log to CloudWatch. The topic's ARN was then set in code and tested with a JSON payload simulating a real request, to confirm the subscription worked.

IAM. A separate role was created to grant the Lambda function permission to read/write event.json and publish messages to the SNS topic. Another test run in the Lambda function verified registration, using the topic's ARN and bucket name from code.

S3. The system maintains the original documents for audit purposes while extracting their data.

Lambda. Configuration → Env. variables.

  • Key: DYNAMODB_TABLE   Value: Receipts — allows changing the target table without code modifications.
  • Key: SES_SENDER_EMAIL   Value: mail@outlook.es
  • Key: SES_RECIPIENT_EMAIL   Value: mail@gmail.com

DynamoDB. After extracting structured data from receipts, the system needs a scalable, high-performance database to store that information. DynamoDB provides consistent, single-digit-millisecond response times at any scale, without the need to manage a database server or worry about capacity planning.
